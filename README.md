# Agent Evolution

[English](README.en.md)

共有スキルの本文について、現在版と改善候補を同じ課題・モデル・推論設定で比較するローカルCLIです。評価対象の接続方式は Claude Code、Codex、OpenCode、Pi で、評価対象は1製品から選べます。[作業終了時の起動確認](OBSERVER.md)は、これらに加えて Grok CLI にも対応しています。終了時に失敗が残った場合だけ人へ起動を提案し、承認後に対象スキルと再現課題の整理を始めます。途中のエラーが解消した場合は提案しません。

## 配布版の状態

このリポジトリは、2026-10-11 に公開した初期スナップショット（コミット `c0b17a4a`）以降の修正を含みます。当時の README にあった「修正前スナップショットで、以後の互換性改善・セキュリティ修正は含まない」という説明は、この版には当てはまりません。

検証について、ここには事実だけを書きます。

- オフラインの単体テスト（pytest と JavaScript）と、モデルを呼ばない `doctor` を、リポジトリルートで実行できます。
- `doctor` は導入済み CLI の有無を一覧します。導入されていない製品は `not_on_path` になります。認証や実モデル応答の形式は、このオフライン診断では未確認です。
- Docker 経路は、製品別の実効設定を読む診断が未実装のため、`settings` 検査が必須の `unverified` となり、実評価を開始しません。
- 新しい証拠条件での実モデル応答と、Docker 評価は未確認です。
- Codex native は特定の版番号の許可リストを使いません。CLI バージョンは省略または `"auto"` で実環境から取得し、明示した場合は完全一致を要求します。

## セットアップ

Python 3.11以降を使用します。リポジトリのルートで次を実行します。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install -e . --no-deps
.venv/bin/agent-evolution --help
.venv/bin/agent-evolution doctor
.venv/bin/agent-evolution demo
```

`demo` はモデルを呼ばず、候補作成・実行記録・比較レポートを作ります。simulationの結果は採用条件を通過しません。

## 実モデルで評価する

1. `examples/codex-smoke.json` をコピーし、スキル、データセット、評価対象、モデル、推論設定、上限を明示します。CLIバージョンは省略または `"auto"` で実環境から取得し、明示した場合は完全一致を要求します。
2. `doctor --config PATH` で選択した対象の必要機能・依存・隔離を確認します。`start` でも検査し、計画、実行環境、スキル・課題をスナップショットします。どちらもモデルを呼びません。
3. `baseline` と `evaluate` がモデルを実行します。

```sh
agent-evolution dataset validate --suite fixtures/bug-investigation-v1.json
agent-evolution doctor --config examples/codex-smoke.json
agent-evolution start --config examples/codex-smoke.json
agent-evolution baseline --run RUN_ID --split train
agent-evolution import-candidate --run RUN_ID --body candidate-body.md
agent-evolution evaluate --run RUN_ID --candidate-sha SHA --split train
agent-evolution select --run RUN_ID --candidate-sha SHA
agent-evolution report --run RUN_ID
```

`candidate-body.md` はfrontmatterを含めず、本文だけを保存します。名前、説明、補助ファイルは変更できません。評価した候補の内容ハッシュを保存・採用まで引き継ぎます。

サンプル設定は2課題×現在版/候補版の4実行だけを許可します。この設定では最終採用のための全評価は実行できません。課題は9件の小規模な動作確認用で、広い実務能力の改善を証明するデータセットではありません。

### 実行環境

- **Codex native**: CLIの必要機能と権限プロファイルを検査します。ユーザー設定、フック、記憶、プラグイン、協調エージェント、Web検索を評価用プロセスで無効化し、モデルと推論設定を明示します。既存ログインをCLI自身が利用し、認証情報をコピー・抽出しません。ツールは課題フォルダへ書き込めますが、スキルは読み取り専用です。課題外の読み書きとツールからのネットワーク接続を拒否するプローブを毎回実行します。
- **Docker**: 4製品のCLIアダプターがあります。CLIを含むdigest固定のイメージが必要です。通常ネットワークは受け付けず、`none` またはモデルゲートウェイへ接続する内部ネットワークを指定します。CLIの接続先・ゲートウェイ認証は用意するイメージで設定してください。ホストの認証フォルダをマウントしません。環境変数による明示したAPI認証だけをサポートします。
- **Simulation**: CLI接続と採用条件の開発用。実モデルでの成功を意味しません。

Codex nativeのネットワーク制限はツール側に適用されます。CLI本体による選択モデルへの接続は必要です。Dockerではイメージとモデルゲートウェイを別途管理します。隔離の確認が失敗した場合、通常のホスト実行へ切り替えません。

実評価には `gitleaks` が必要です。候補・課題・生成ファイルのスキャンが失敗した場合は評価を無効にします。秘密検出は外部送信可能なデータを指定する責任を代替しません。

ファイル検査は評価対象から書けない一時コピーに対して行い、管理側の固定設定でGitleaks組込みルールを使います。作業領域の `.gitleaks.toml`、継承された `GITLEAKS_*`、`gitleaks:allow` による抑止は採用しません。ルートに `.gitleaksignore` がある対象と通常ファイル・ディレクトリ以外の対象は拒否します。元のファイルは削除・変更しません。

コピーとスキャンには合計30秒の枠があり、失敗や時間超過は評価不合格です。各検査で一時容量とI/Oが増えます。例示用トークンの誤検知も自動で除外せず、課題を見直すか、管理側ポリシーの具体的な変更案を人が承認します。スキャナーの既定allowlistは維持します。実装更新後は既存runを再開せず、新しいrunで比較してください。

実モデルを使うrunでは、課題・スキル・候補の新規保存前、評価・候補生成のプロンプト送信前、受信した標準出力・標準エラー、解析後の操作記録・保存する成果物にも同じ固定ポリシーを適用します。JSONの文字列を復号した値も検査し、従来の簡易検出も維持します。テキストは標準入力からGitleaksへ渡し、検査用の本文ファイルは作りません。検査専用の見出しを加えてテキストとして扱い、NUL文字を含む入力は拒否します。モデルへの送信文や保存する証拠そのものは書き換えません。

秘密の検出、検査失敗、時間超過があればその処理を停止します。受信内容の検査は失敗・時間超過したエージェントにも行い、伏字化・切捨てより先に全文を確認します。検出された回のログ本文・証拠は保存せず、値を含まない理由だけを記録します。そのため、問題の回の本文を使った原因調査はできなくなります。正常な回は従来どおり必要な証拠を保存します。

テキスト検査1回にも30秒の予算があり、検査回数とメモリ使用量が増えます。終了処理等まで含む厳密な総時間上限ではありません。検出器で判断できない場合に検査を省略して続行はしません。モデル実行前に拒否されても既に予約した開始回数は返却せず、受信後の拒否でも既に発生したモデル利用量・費用は戻りません。Gitleaks自体の外部送信・モデル呼出しはありません。

simulationだけのrunは、Gitleaks不要のオフラインデモという従来の用途を維持し、この追加検査の対象にしません。過去のDB・レポートや利用者が用意した元入力ファイルは自動検査・消去しません。任意の暗号化・符号化を復元する検査、製品自身の履歴、残留プロセスの終了管理、採点と保存の間の競合対策は対象外です。新規に保存する成果物は読み込んだ内容そのものを検査しますが、採点時と同一だったことまでは保証しません。

`doctor` 単独はインストール状況の一覧です。`doctor --config PATH` は選択した対象だけを検査し、項目ごとに `passed` / `failed` / `unverified` と理由を表示します。未選択のDocker等は要求しません。必須条件が未確認または不合格なら実行可能とは判定しません。認証・実モデル応答のイベント形式は、このオフライン診断では未確認です。

Codexの引数受理は `exec --help`、明示した機能設定は `features list`、OS隔離は `sandbox` で検査します。`features list` は通常設定を読み込む診断経路であり、`exec --ignore-user-config --ignore-rules --strict-config` の実モデル経路全体を検証した意味ではありません。実行時にも指定を維持し、必要な証拠を確認できなければ評価を不合格にします。DockerイメージにはCLIに加え、隔離検査用の `python3` が必要です。

Docker接続では、製品別の実効設定を読む診断が未実装のため、現在の `settings` 検査は必須の `unverified` となり実評価を開始しません。digest固定・一時HOME・help受理だけで利用者設定や追加機能の排除まで確認済みとは扱いません。実効設定の検査とDocker実環境での確認を追加するまで、この経路は利用不可です。

特定の版番号の許可リストは使いません。必要条件を満たす新版は新規runに利用でき、実際のCLI・版・実体識別情報、接続コード、設定、隔離方式をrunへ記録します。評価・生成の前に照合し、途中の更新を検出したら、そのrunでの追加実行を予算消費前に拒否します。検査では将来の意味変更を完全には検出できないため、実評価の正常終了・ツール結果・スキル読込の証拠も毎回検証します。

共有スキルの手動利用は、スキルを読んで共通CLIを実行できるエージェントを対象にします。自動監視と評価実行には製品別の接続コードが必要です。新製品を追加する際は接続コードとテストを用意し、未知の製品を別製品として実行しません。

## GEPAによる候補生成

`gepa==0.1.4` を直接利用します。実行モデルと候補生成モデルを独立したプロファイルとして指定できます。初期設定では補助採点LLMを呼びません。

```sh
agent-evolution evolve --run RUN_ID
```

この操作にはconfigの `generator` と、0より大きい `budget.max_generations` が必要です。生成プロファイルもCLIを利用するため、Codex nativeなら既存ログインを使えます。別のAPIキーを必須にはしていません。自動的に高性能モデルへ切り替えません。

GEPAはtrainの課題と失敗チェックを使って本文を修正し、validationで候補を選択します。holdoutは渡しません。同一候補・課題・設定・反復番号の結果は同一run内で再利用します。

生成時にはtrainの正規化した操作記録と成果物も渡します。実行・生成のモデルや推論量は設定どおりに固定し、強いモデルへの自動切り替えは行いません。

## 最終確認と採用

```sh
agent-evolution finalize --run RUN_ID
agent-evolution report --run RUN_ID
# レポートと差分を人が確認した後
agent-evolution approve --run RUN_ID --candidate-sha SHA --report-sha REPORT_SHA
agent-evolution promote --run RUN_ID --candidate-sha SHA --report-sha REPORT_SHA
agent-evolution rollback --promotion PROMOTION_ID
```

`finalize` は候補を固定し、現在版と候補版をholdoutで反復比較します。候補固定後の再探索は禁止し、同じholdoutを別runから再利用する操作も拒否します。既定は最低5課題グループ・3反復。成功率、グループ単位のbootstrap区間、必須チェック、時間増加を確認します。少数課題の信頼区間には限界があるため、代表的な実務課題を増やしてから採用してください。

未選択製品は `not_selected`、取得できない費用は `unknown`。必須対象の失敗を黙って除外しません。エラー、未読、秘密検出、simulation、0件評価では採用できません。

承認は候補ハッシュ・レポートハッシュ・適用先に紐付きます。正本が評価後に編集されていたら適用を拒否します。変更前のスナップショットをSQLiteに保存してから原子的にSKILL.mdを置換します。復元時も後からの編集を上書きしません。

## 中断・再開・費用

```sh
agent-evolution cancel --run RUN_ID
```

予算はSQLiteで実行開始前に予約します。CLI内部のAPI往復数ではなく、評価タスク開始数・生成開始数・経過時間を制限します。API金額の厳密な上限を保証するものではありません。失敗した開始も消費に数え、自動再試行しません。

同じrunで同じコマンドを再実行すると完了済み評価を再利用します。壁時計の期限はrun作成時から進み、再起動でリセットしません。キャンセルしたrunの再開や、実装・設定変更後のrun再利用は拒否します。新しいrunを作る場合は予算も新たに設定してください。

標準の保存先は作業ディレクトリの `.evolution/`。`--state PATH` で明示できます。`reports/<run>/report.md`、`report.json`、`skill.diff` と比較したSKILL.mdを出力します。生のモデル思考過程は保存せず、操作・結果・使用量を正規化して記録します。

評価と終了監視の保存先は、利用者本人が所有するディレクトリ0700・通常ファイル0600に限定します。保存先までのシンボリックリンク、通常ファイルのハードリンク、保存先内のACLを拒否し、DB・補助ファイル・レポート・操作記録・取消ファイル・ロックの読み書きでも検査します。保存先内に置く設定・課題・スキルにも同じ条件を適用します。既存の不適切な権限を通常操作で自動修正することはありません。

`schema`、`dataset validate`、`doctor --config`も、選択した保存先が既に存在すれば最上位までの経路を検査します。入力が保存先の外でも、選択した保存先が不適合なら拒否します。保存先がまだなければ、外部入力の確認だけで保存先やDBを作ることはありません。

保存先の親はrootまたは本人の所有とし、グループ・他ユーザーの書込みを拒否します。親にある拒否専用ACLは許可します。OS標準のroot所有sticky一時ディレクトリは例外ですが、その下は本人所有が必要です。macOSの `/tmp` のような別名リンクは使わず、実体の絶対パスを指定してください。これらの検査は、同じユーザー権限で動く悪意あるプロセスや、検査直後の差替えを隔離するものではありません。

新しい保存先には、全内容を通常のGit追加から除外する `.gitignore` を0600で作ります。既存の除外ファイルは内容が `*` または `*` と末尾改行だけの場合に受け付けます。すでにGitへ追加済みの記録、強制追加、同期・手動コピーは防ぎません。共有フォルダやリンクで保存先を運用していた場合は、新しい条件に合う場所へ移す必要があります。

この実装更新前のrunは、追加評価・候補生成・承認・採用に再利用できません。保存済み記録は消しません。新規runで実モデル評価を行う際は、新たな予算が必要です。終了監視の更新後はCodexのフック再信頼と各製品の再読込みが必要です。

### 実行とスキル本文の証拠

再現コマンドとスキルの読み込みは、それぞれ独立したツール呼び出しで実行させます。採点で受け付けるコマンドは、1回の呼出しに1個のリテラルなコマンドだけです。シェルを使う場合は `/bin/sh -c`、`/bin/bash -c`、`/bin/zsh -c` と本文1引数だけを認めます。ログインシェルの `-lc`、後続コマンド、export、環境変数代入、リダイレクト、展開、コメント、改行は証拠にしません。引用符の中でも演算子・変数展開・globなどに使う特殊文字は拒否します。これは実行コマンドを制限する権限設定ではなく、評価証拠として採点する形式の制限です。

スキルはRunnerが指定する絶対パスと完全一致することを要求します。`cat` 経由では `/bin/cat` または `/usr/bin/cat` に対象ファイル1個だけを渡し、CLIが成功を報告した操作の出力が固定したSKILL.md全文と一致した場合にだけ認めます。別パスの同名ファイル、相対パス、自作cat、オプション付きcat、部分出力、出力省略は不採点です。組込みReadにも絶対パス・引数・全文一致を要求し、offset/limit等での部分読み込みを認めません。

ClaudeにはReadを指示し、対応する単一tool_resultと構造化された `file.content`、結果のファイルパス、全行範囲、切捨ての有無を確認します。行番号付きの表示文字列を本文とは扱いません。BOMや改行形式の変換、出力上限、未対応のイベント形式により全文一致を確認できない場合も拒否します。ClaudeのBash出力は空白等が加工される版があるため、スキル読込の推奨経路にしません。

Codex、OpenCode、Piのコマンドには完了状態と整数の終了コード0を要求します。ClaudeのBashは対応する非エラー結果に加えて、前景処理の完了情報を確認し、中断・バックグラウンド開始・非0終了の成功解釈を除外します。Claudeの公開出力には数値の終了コードがないため、確認できるのはCLIの成功報告です。通常のtask評価でスキル全文を確認できなければ、成果物が正しくても合格証拠を保存しません。simulationは引き続き実モデル証拠から除外します。

この検査は、信頼するCLIが操作の成功を報告し、対象スキル全文がツール結果に返ったことを確認します。OSでどの実行ファイルが動いたか、実際のfile-open、課題処理前に読んだ順序、モデルAPI内部のコンテキストへの収録、モデルの理解・遵守は証明しません。シェル関数等によるコマンドの置換は別の制約です。`command_observed` は一致する単一コマンドの成功報告を採点しますが、Codex JSONLにはcwdがないため、相対パスのスクリプトがどのディレクトリから実行されたかは証明できません。

既存runは実装ハッシュの変更により再開できず、新しいrunが必要です。正常な操作でも形式が合わなければ評価は失敗し、消費済みの開始回数やモデル費用は返りません。追加のモデル呼出しや依存導入はありませんが、全文を取得するために出力・トークン量が増える場合があります。新しい証拠条件での実モデル応答とDocker評価は未確認です。Dockerの既存の開始拒否も継続します。環境固有のPython絶対パスを含むローカル用サンプルは、この配布には含めていません。
